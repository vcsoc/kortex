## Implemented

- `kortex serve --mcp stdio` calls the same real rmcp stdio server as `kortex mcp --transport stdio`. Explicit host, port, and authentication flags conflict with the alias. No HTTP listener, network feature, mutation tool, SQL, or shell tool was added. Plain `serve` remains the honest P1 `NOT_IMPLEMENTED` error; existing unauthenticated non-loopback refusal remains intact.
- Stdio-mode runtime and argument-parse errors stay on stderr even with `--json`. Non-protocol CLI JSON error behavior is unchanged. Explicit help/completion remain ordinary CLI output.
- MCP validation enforces advertised string lengths/minima, integer bounds, booleans, enum values, required fields, unknown-field rejection, staged/unstaged exclusion, and opaque cursor syntax. `list_repos` no longer advertises repository/freshness arguments that it cannot honor. Inputs are bounded to 64 KiB per stdio line; oversize frames close the transport rather than fabricate a tool response.
- Tool annotations remain read-only, non-destructive, idempotent, and closed-world. Output schemas describe the actual versioned success/error envelope, not invented per-operation data fields. The graph-schema resource includes the source-backed `REFERENCES` and `USES_TYPE` kinds added by the semantics worker.
- Both tool and resource work share the same four permits, 10-second deadline, and cancellation selection. Blocking resource reads no longer run directly on the async executor. Detached timed-out/cancelled workers keep their permit until they actually finish.
- Tool budgets count the serialized rmcp result (including text/structured duplication) plus a 512-byte protocol reserve. Independent search/repository hits may be paged; graph neighborhoods and evidence paths are never cut into misleading partial objects. Error messages are shortened, preserving code/exit code, so error results fit the minimum 1024-byte tool budget.
- Resource budgets count serialized resource results, including nested JSON escaping, plus the same reserve. All resources have a 128 KiB ceiling; selected status also honors the smaller repository-configured MCP response budget. Oversize resources return a structured `RESPONSE_BUDGET` protocol error and direct clients toward bounded tools. Registry tools retain a fixed 256 KiB ceiling because they have no single selected repository.
- MCP query cursors now pin repository ID, indexed generation, and query text. Repository-list cursors pin the returned registry metadata (including freshness). Numeric legacy MCP cursors, changed-generation/query/repository cursors, malformed cursors, and offsets above 100000 are rejected as `INVALID_CURSOR`; clients must restart pagination. The internal shared Service still receives its existing numeric offsets. Budget-driven repagination emits the correct pinned continuation without skipping hits. Cursors are consistency tokens, not authorization or cryptographic signatures.
