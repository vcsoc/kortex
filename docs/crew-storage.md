### Exact remaining security/platform gates

Windows **ACL/owner privacy is not implemented**: storage `owner` intentionally performs Unix UID checks only, and Unix 0700/0600 mode branches do not enforce Windows privacy. `cap-std` secures path traversal, not ACL inheritance/current-token ownership. Candidate source review did not justify adding an ACL implementation without Windows runtime evidence: `windows-permissions 0.2.4`'s File trait uses SE_UNKNOWN_OBJECT_TYPE, and its `set_multiple` derives DACL/SACL selection from the group option; `windows-acl 0.3.0` exposes raw-pointer SID helpers and requires further safety review; `winsafe 0.0.29` provides the reviewed MoveFile wrapper but no GetSecurityInfo/GetNamedSecurityInfo wrapper. None of those ACL candidates was added or treated as privacy enforcement. Need an audited safe owner/DACL implementation, owner-only creation before writing derived source, permissive/inherited/foreign-owner denial fixtures, and actual Windows execution. The current Windows index/cache must **not** be represented as verified private production storage.

SQLite/repair **same-user ancestor replacement remains unresolved**: `check_index_directory` and artifact checks happen before SQLite/acquire_writer opens absolute paths; SQLITE_OPEN_NOFOLLOW protects the final DB, not replaced parent directories. `has_future_version` and preservation inventory/moves also resolve ambient ancestors, so the no-replace improvement prevents target overwrites but is **not descriptor-rooted repair**. A same-user process ignoring the advisory lock can rename/recreate ancestors/artifacts between checks. A complete solution needs an audited handle-bound SQLite VFS/parent-pinning design and descriptor-relative repair/inventory/locking, not more check-then-open wrappers or destructive race demonstrations. This slice deliberately did not run destructive evidence-loss experiments on real indexes. Existing data, backups and parent edits are preserved.

### Implemented behavior

- Shared cache: `Store::directory_for(root, "user-cache")` selects `$XDG_CACHE_HOME/kortex/indexes/<BLAKE3(canonical-root)>`, falling back to `LOCALAPPDATA`, then `$HOME/.cache`. No basename/remote-URL aliasing; no repository-supplied arbitrary cache directory. Canonical aliases share the same lock, independent clones do not. Cache-home/Kortex/index parents and hash leaf require safe current-user ownership and no group/world writes on Unix. New directories are 0700, DB/lock/registry files 0600. Existing unsafe directories are refused, never silently chmodded/adopted.
- Reserved `index-owner.json` binds an index to its canonical root. Missing legacy markers remain readable; successful writable opens create a marker. A copied/moved index with another root's marker returns `INDEX_IDENTITY` until explicitly preserved/rebuilt. Markers are data, never executable configuration.
- Known pre-versioned Kortex schema 0 migrates transactionally to schema 1 with `schema_migrations` and application/parser/schema `storage_versions` records. Existing schema-1 migration records must agree with `user_version`. No parent-controlled schema/parser version was bumped. Before migrating a nonempty recognized schema, SQLite `VACUUM INTO` creates a unique private consistent backup (including committed WAL pages). Unknown schemas and future schemas are refused. This wave has **no destructive schema migration**; backups precede even the supported additive legacy migration. Failed migrations roll back and retain the backup and original active generation.
- `Store::repair(root, storage)` is **explicit preservation, not a fabricated rebuild**. After the writer lock and regular-file/UID/hard-link/symlink checks, it renames only `index.db`, WAL/SHM/rollback journal and `index-owner.json` into a unique private `repair-*` directory. Original bytes/inodes/Unix ownership/modes survive. A durable `preservation.json` inventory precedes moves. Move failure attempts rollback without deleting either location; errors identify the evidence directory. Future versions are refused from main DB headers and even uncheckpointed page-one WAL frames without opening/checkpointing SQLite. Unknown files, previous backups, source/config and writer-lock files are never moved/deleted. `RepairReport { backup_directory: PathBuf, preserved_files: Vec<String> }` reports preservation only; callers must subsequently rebuild and verify the new generation. Interrupted repair may leave artifacts split between the original and inventoried backup directory; retain both and inspect, never auto-delete.
- `integrity()` now detects FK failures, active-generation file/node/edge/FTS count disagreement, missing FTS identities and invalid committed snapshot JSON, not only SQLite physical integrity. It does not claim exhaustive semantic validation of source facts.
- SQLite opens request `SQLITE_OPEN_NOFOLLOW`; all DB sidecars (including rollback journals), locks and registry files are checked for symlinks/hard links/foreign UID. Registry creation inherits private placement checks. Repository Unix reads now walk canonical relative components through `openat` directory descriptors with `NOFOLLOW`, so a replaced leaf or parent cannot escape after canonicalization. `NONBLOCK` plus regular-file checks also refuses FIFOs without hanging. Internal confined aliases still work. Native watch implementation was not edited; its confined nonrecursive registration and no-external-symlink-wakeup tests continue passing.
- Real v1 workspace TOML loader accepts relative/absolute repository lists, normalizes guarded Git roots and deduplicates, caps file size/repository count, rejects unknown fields/versions and never executes manifest content. Both live-filesystem and Git-index case collisions return `CASE_COLLISION`; the latter fixture works on this case-insensitive macOS filesystem. A legitimate unstaged case-only rename remains indexable.
- Config root relocation is implemented via `Config::resolved_root(base)`. Repository `.kortex.toml` relocation is canonicalized and confined under the invocation root; trusted user/explicit config can intentionally choose another directory. Files are bounded to 1 MiB, unknown fields stay rejected. HTTP/model capability activation or redirection from repository config is refused; trusted user/explicit config/env may enable real peer implementations. `auth_token_env` stores a variable NAME only, never its value. Non-loopback enabled HTTP requires explicit auth-name and repository allowlist. Exact CORS origins only, no wildcard/credential/path origins. Local embeddings require an explicit absolute regular artifact, version and 64-hex BLAKE3 checksum; artifact digest/runtime/license verification belongs to the search implementation. No silent downloads.
