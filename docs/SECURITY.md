## Authority And Operation

Repositories are untrusted DATA. Kortex parses files; it must never install dependencies, execute indexed source/build scripts/tests/hooks, fetch grammars, upload source or silently activate models. Source instructions remain data, not agent directives. MCP inspection is read-only. Optional HTTP requires explicit trusted opt-in, authentication/loopback restrictions and local assets; there is no automatic listener, CDN or telemetry. Repository configuration cannot activate or redirect trusted HTTP/model policy. Models require explicitly supplied local artifacts and owner licensing/relevance acceptance; that acceptance is still absent.

Source confinement uses held descriptors, no-follow actual reads, current root/parent/leaf observations, bounds, EOF and real content hashes. Parent rejected root-check amortization because it weakens current namespace observations. Reusable initialized64KiB scratch changes storage allocation, not authority or freshness. Initial root/ancestor acquisition must be trusted; ordinary reads/two-observation checks do not prove arbitrary-writer atomicity, and endpoint checks do not rule out every ABA substitution.

Git uses a trusted installed executable, argument arrays (no shell), bounded output/deadlines, disabled external diff/text conversion/fsmonitor hooks. Untrusted Git metadata, linked-worktree/commondir and inherited policy authority require explicit treatment; a successful local Git invocation is not a blanket grant to outside bytes. No remote operation, source upload or indexed-code execution is authorized.

## Storage And Resource Boundaries

Derived data contains signatures, comments, citations and architectural facts: protect it like source. Unix private placement requires restrictive ownership/modes and actual ACL policy; Darwin extended ALLOW/unknown entries refuse rather than being stripped. Windows private derived storage still fails closed pending a real supported DACL backend/runtime proof. Source-read authority is distinct from derived-data privacy. Same-UID/admin isolation and coarse/network-filesystem guarantees are not accepted.

SQLite uses bound parameters, WAL transactions and pinned readers. Query-only required-evidence approval cannot authorize full graph integrity; full reads still check unused edge evidence. Used malformed evidence refuses; genuine legacy absence permits same-Store fallback. A successful query is not global graph-health certification.

Aggregate fact/resolution/AST guards use typed RESOURCE_LIMIT/exit9 and abort publication rather than truncate candidates or return false exactness. Cached facts are charged before retention; old trusted unbounded APIs remain compatibility interfaces. Per-emission32MiB exact serialized admission is integrated for fresh/cached production indexing, but native parser memory, single-record/pre-admission construction, old-snapshot loading and resolver temporary/cache memory remain incompletely bounded. Counts/serialized bytes are NOT heap/RSS/OOM proofs. See docs/RESOURCE_BOUNDARIES.md.

## Remaining Acceptance

Full current-source Linux/coverage/browser/package/install validation must follow substantive integration. Further gates include foreign-UID and namespace adversaries, Windows runtime/privacy, broad parser/property/JSON fuzzing, ENOSPC/fsync/power-loss recovery, ambient SQLite VFS binding, dependency/legal/signing review, executable reproducibility and real editor-client acceptance. Local-only tests and cross-compilation do not waive them. Impact and risk are conservative evidence, not proof of runtime safety or breakage; ambiguity, uncertainty, staleness and traversal budgets must remain explicit.
