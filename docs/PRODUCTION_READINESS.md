## Execution and ownership

Continue in bounded implementation/integration waves with the same four workers. Shared checkout has no initial commit; do not reset, clean, discard, push, publish or create worktrees that cannot see current files. Parent owns core contracts, workspace dependency resolution/lockfile, shared documentation, independent review and final acceptance. Workers may add crate-local dependencies after declaring version/features/license rationale; parent owns lockfile reconciliation. No nested delegation.

- Semantic worker: parse/languages/indexer production and their tests; P0 module/receiver gaps and P1 Java/C#/C/C++/Ruby/PHP providers.
- Persistence worker: repo/storage/config and their tests; workspace/cache/migrations/recovery, isolation, policy and security failures.
- Application worker: analysis/search/graph and their tests; routes/tests/processes, architecture rules, public contracts and real opt-in local hybrid retrieval.
- Transport worker: CLI/MCP/HTTP and their tests; secure optional HTTP/OpenAPI and explorer integration after frontend owner approval.

Public APIs must remain compatible while peers implement additions. Use additive functions/serde-defaulted metadata, communicate cross-owner requirements, and never introduce synthetic success to bridge unfinished dependencies. Parent controls parser/schema version changes and shared compatibility decisions.
