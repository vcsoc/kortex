# Performance and correctness measurements

Targets in the specification are acceptance goals, not claims. Raw local smoke results are in `benchmark-local.json`, generated by:

```sh
cargo build --release --locked -p kortex-cli
python3 benches/smoke.py
```

Local hardware: Apple M5 Pro, aarch64 macOS 26.5.2; Rust 1.99.1, optimized release profile (thin LTO, stripped). The deterministic generated dataset has 200 Python files, five functions per file, 1,000 functions plus 200 file nodes and 1,800 declaration/call edges. Commands measure full native process lifetime, including freshness reconciliation, against a warm local filesystem. No baseline comparison to another product is made.

| Operation | Samples | Observed result |
|---|---|---|
| version --json startup | 100 | p95 ~5.02 ms |
| full index --verify | 1 | ~105.89 ms |
| query | 20 | p95 ~42.49 ms |
| context | 20 | p95 ~46.18 ms |
| impact | 20 | p95 ~38.72 ms |
| one-file incremental --verify | 1 | ~132.65 ms, 1 parsed / 199 reused |

These are smoke observations, not reference-scale acceptance: 100k symbols, 10k files, 1,000 representative queries, cold-start distributions, peak RSS, repeated edit-to-watch latency and relevance/precision/recall datasets remain pending. A single incremental sample is not a p95 measurement.

## Algorithmic limitations

Unchanged per-file facts are cached by content/parser/config fingerprints. Changed files parse in a bounded native Rayon pool. Global resolution, graph serialization, SQLite staging and FTS population currently rebuild for each generation. Query services deserialize a complete graph snapshot and reconcile source hashes; they do not yet use a bounded persistent service snapshot/connection pool. These choices prioritize transactional correctness but require scale profiling and optimization before performance release claims.

## Correctness evidence

Fixture tests assert direct-call/import behavior, actual spans, missing/ambiguous targets, shadowing/export visibility, unrelated names and malformed syntax. Full/incremental facts and edges are compared, including renamed/deleted files. BFS reachability and every returned evidence path are exhaustively checked against independent transitive closure for all 4,096 loop-free directed four-node graph configurations. Killed-writer rollback and old-reader graph/FTS consistency are tested.

Those finite assertions are not a broad language precision/recall or search relevance evaluation. Measured with cargo-llvm-cov 0.9.1 and official Rust 1.99.1 LLVM tools: 90.92% workspace line coverage. Critical storage/repo sources measure 92.30%; the 90% threshold command exits 0. Both configured line-coverage targets pass locally after all four crew tracks and parent integration. These are line metrics, not proof of semantic completeness.
