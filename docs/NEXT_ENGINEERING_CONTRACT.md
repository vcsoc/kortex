## Shared control primitive already implemented by parent

`kortex_core::RequestControl` is Clone/Send/Sync with shared atomic cancellation and immutable monotonic deadline. Methods: `new(Duration)->Result<Self>`, `from_deadline(Instant)`, `cancel`, `is_cancelled`, `deadline`, `remaining`, `check()->Result<()>`, `restrict_deadline(Instant)->Self`. Restriction preserves shared cancellation and NEVER extends a parent's deadline. Errors CANCELLED/TIMEOUT exit9. No serialization/config/persistence changes or new dependencies.

Application: expose additive `Service::execute_with_control(&self, operation:&str, args:&Value, control:&RequestControl)->Result<Value>`; retain execute and explicit experimental local-model APIs. Combine requested/configured limits with restrict_deadline, not a new unrelated token. Check in actual traversal/ranking/AST/inventory loops, not only before/after all work. Repository and graph APIs can add control-aware variants without breaking current callers. Transport creates/passes one token before blocking work, cancels it on disconnect/deadline, and keeps the permit until actual completion. A token cannot force-stop an already running kernel I/O or indivisible native operator; no such guarantee may be claimed.
